2026-09-10 打通。过程中踩到三个坑，都已解决：
① 只开 443、没有 80 —— 明文 HTTP 不通，必须走 TLS；用固件自带的 ISRG Root X1 校验，没用 setInsecure()。
② 无条件 gzip —— 即使声明 Accept-Encoding: identity，服务端仍回 gzip。 用 ESP32-S3 ROM 里的 miniz 解压，只占 916 字节 flash。
③ TLS 握手爆栈 —— loopTask 默认 8 KB 栈会崩，已提到 16 KB。
顺序要求：TLS 要校验证书有效期，所以必须 先 ntp 再 weather。 顺序不对时会明确报「系统时间未同步」，而不是含糊的网络错误。

⑤ ChatGPT 用量：走自建 sub2api

你已经有自建的 sub2api 服务，这是三种方案里最好的一种——key 权限可控，不用把 OpenAI 的 Admin key 放到设备上。

要接它，需要你提供三样东西（不急，按你说的排后面）：

需要说明
服务地址形如 https://你的域名，以及它是否暴露在公网（ESP32 要能直连）
用量接口路径sub2api 一般有 /api/user/… 或 OpenAI 兼容的 /v1/dashboard/billing/…。 你把它的接口文档或 /docs 页面发我，我来定用哪个
一枚只读 key专门给设备用的，权限只够查用量。不要用管理员 key
接入前我会先做的验证：在你的 Mac 上用 curl 打一遍接口，确认返回结构、字段名和数值单位（是 token 数？美元？百分比？）， 再决定屏幕上画进度条还是数字。避免把"看起来对"的字段写进固件。

还需要你定的两件事

  • 昵称：显示什么？以及怎么设置它（串口命令 / 配网页面 / 写死）。
  • 和风的 API Host：见上方「和风接入进度」——这是当前唯一卡住天气页的东西。
另外一个必须提前想的问题：现在的 Wi-Fi 连接是一次性测试、只存 RAM（我们特意没写 NVS，还验证过）。 但产品化必须让设备记住 Wi-Fi 和 API key——也就是要写 NVS。 而 NVS 在 flash 里是可以读出来的，所以 API key 存在设备上等于半公开。 建议：天气这类低价值 key 存 NVS 可以接受；OpenAI 的 key 不要放设备上，走中转服务。
