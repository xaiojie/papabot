# 轮子 vs 腿 · 方案对比分析

> 2026-09-14 · 决策依据：集成板**尚未下单**，结构 A5 是腿式

---

## 一句话结论

**换轮子会让工程量和失败率大幅下降，代价是失去「走路」这个萌点。**
**而且集成板不用改一行 —— PCA9685 驱动的信号和轮子完全兼容。**

---

## 一、直接对比

| 维度 | 腿（现在的方案）| 轮子 |
|---|---|---|
| **舵机数** | 8（每腿髋+膝）| **2–4** |
| **剩余通道** | 0 | **4–6 可复用**（云台/手臂/尾巴）|
| **需要步态引擎** | ✅ 必须有（最难的模块）| ❌ **不需要** |
| **需要逆运动学** | ✅ 需要 | ❌ 不需要 |
| **需要 IMU** | 强烈建议 | ❌ 不需要（差速驱动天生稳）|
| **会摔吗** | 会，且没有闭环 | ❌ 不会 |
| **速度** | 5–10 cm/s | **30–50 cm/s** |
| **行走电流** | 2–3 A（堵转 12 A）| **0.3–1 A** |
| **扭矩余量** | 4.7 倍（勉强）| **很宽裕**（滚动摩擦极小）|
| **代码量** | 步态 ~300 行 + IK ~100 行 | **差速控制 ~50 行** |
| **机械复杂度** | 8 个舵机座 + 上下腿 + 脚垫 | 底盘 + 2 个轮 + 1 个万向轮 |
| **能越障吗** | 一点点（抬腿）| ❌ 完全不能 |
| **萌度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

---

## 二、⭐ 关键：集成板完全不用改

**PCA9685 输出的是标准 RC 舵机信号（50Hz，脉宽 1000–2000µs）。**

**连续旋转舵机（360° 舵机）用的是同一套信号：**

```
1500µs  = 停
<1500µs = 反转（1000µs 最快）
>1500µs = 正转（2000µs 最快）
```

**所以：**

| | 要不要改 |
|---|---|
| 集成板 PCB | ❌ **不用改** |
| 立创 BOM | ❌ 不用改（只是舵机型号换）|
| 固件命令 | ❌ 不用改（`servo pulse` 照样用）|
| 云端控制 | ❌ 不用改 |
| 机械结构 | ✅ **要重做底盘** |

**舵机本身换成 360° 版本即可**，接口、尺寸、供电全都一样。

## 三、三种轮式方案

### 方案 ① 两轮差速 + 万向轮（推荐）⭐

```
左轮舵机 ──┐
           ├── 差速转向（像坦克）
右轮舵机 ──┘
                       + 前后各一个万向轮/牛眼轮
```

| 项 | 值 |
|---|---|
| 舵机数 | **2** |
| 剩余通道 | **6** |
| 控制 | 左轮速度 + 右轮速度 → 直行/转向/原地旋转 |
| 优点 | 最简单，转向半径 0（能原地转）|
| 缺点 | 两轮平衡靠万向轮支撑 |

### 方案 ② 四轮驱动

```
4 个 360° 舵机，左右各两个
```

| 项 | 值 |
|---|---|
| 舵机数 | **4** |
| 剩余通道 | 4 |
| 优点 | 抓地好，能爬小坡 |
| 缺点 | 没有差速器，转弯时轮胎会打滑（滑动转向）|

### 方案 ③ 两轮 + 云台

```
2 个轮子 + 2 个舵机做云台（屏幕能转头）
```

**这个有意思** —— 用剩下的通道让**屏幕能左右转**，
配合表情和视线追踪，「看着你」的效果会很好 ✓

## 四、换轮子之后能做什么

```
✅ 平滑移动（30–50 cm/s）
✅ 原地旋转
✅ 手机/手柄遥控，延迟完全够用
✅ 不用 IMU、不用步态引擎
✅ 不会摔，稳定
✅ 屏幕/表情/语音全程同步
✅ 【多余通道还能加云台/手臂/尾巴】
```

## 换轮子之后失去什么

```
❌ 不能上台阶、越障、走地毯
❌ 「四足行走」这个演示效果没了
❌ 桌面宠物「爬来爬去」的萌点降一档
```

## 五、💡 我的真实建议

### 先问一个问题：这个项目的核心价值在哪？

```
屏幕 + 表情 + 语音 + 云控制 + AI 对话   ← 这些是差异化亮点
              ↑
        占了 80% 的「这个产品有意思」的部分

四足行走                                 ← 这是实现难度最高、收益最低的部分
              ↑
        占 80% 的开发时间，贡献 20% 的观感
```

**用腿：**
```
第 1 阶段  单腿标定           ← 现在
第 2 阶段  四腿站姿
第 3 阶段  爬行步态引擎       ← 最难，容易卡住
第 4 阶段  调平衡、调地面接触  ← 反复迭代
第 5 阶段  才能遥控走路
          ...然后发现还是走不快、会摔
```

**用轮子：**
```
第 1 阶段  装轮子 + 写差速控制   ← 一两天
第 2 阶段  网页/手柄遥控         ← 复用现有网页
第 3 阶段  直接开始做语音/表情/AI ← 项目的真正亮点
```

### 折中方案（如果舍不得腿）

**保留结构 A5 的腿，但先不做步态** —— 让它「站着 + 屏幕 + 表情 + 语音」，
这已经是一个很完整的桌面宠物了 ✓
**等前端软件都做完，再回头啃步态。**

## 六、决策要点

| 如果 | 那么 |
|---|---|
| 想要**快点看到能动、好玩** | **换轮子** ⭐ |
| 想要**四足行走的演示效果** | 保留腿，但要有心理准备 |
| 想要**两者兼顾** | 底盘做成可换的：腿模块 / 轮模块互换 |

### ⏰ 时间窗口

```
集成板   尚未下单 ✓  ← 现在改舵机型号不用付代价
结构 A5  是腿式，换轮子要重做底盘（但底盘比腿简单得多）
报价单   24 小时内有效
```

**核心：PCB 不用改，所以换轮子的成本主要就是「重做底盘 + 换舵机型号」。**
