**控制台改走原生 USB，不走 CH340。** CH340（`1A86:7523`）在 USB 总线上枚举成功，但 macOS 不带 CH34x 驱动，因此没有生成 `/dev` 节点；`kextstat` 中无任何 CH34x/WCH 驱动。实测改用板载 USB-Serial/JTAG（`303A:1001` → `/dev/cu.usbmodem*`），**无需安装驱动**，烧录（`Hash of data verified`）与双向串口均通过。该板一个 Type-C 口经 WCH USB HUB 同时接出 CH340 与原生 USB 两路，与厂家原理图一致。

为此新增编译环境 `lckfb_s3_usbjtag`：`ARDUINO_USB_MODE=1` + `ARDUINO_USB_CDC_ON_BOOT=1`，使 `Serial` 指向 USB-Serial/JTAG。该环境**故意不挂 `export_firmware.py`**，不会覆盖默认环境已验证的交付镜像；实测确认 `artifacts/firmware/` 逐字节未变。

已知限制：按 RST 时 USB 会重新枚举，开机横幅早于端口重新打开，**该控制台抓不到开机提示**（UART 控制台无此问题）。改用 `status` 的 `uptime_ms` 判断是否刚复位。

### 本次修复：PSRAM 严格相等判定

实机首次运行报 `FAIL PSRAM: 8386295 bytes, expected 8388608`。查 Arduino-ESP32 `cores/esp32/ESP.cpp` 确认：

```cpp
uint32_t EspClass::getPsramSize(void) {
  if(psramFound()){
    multi_heap_info_t info;
    heap_caps_get_info(&info, MALLOC_CAP_SPIRAM);
    return info.total_free_bytes + info.total_allocated_bytes;  // 堆管理总量，非裸容量
  }
  return 0;
}
```

它返回的是**堆分配器管理的 PSRAM 总量**，比物理容量少一块保留区，因此与标称值做 `==` 在健康硬件上必然失败。这是一处**固件判定缺陷，不是硬件缺陷**：esptool 报 `Embedded PSRAM 8MB`，64KiB 样本测试 PASS，`largest_block=8257524`（与真实 8MB 器件相符）。

修复：新增纯函数 `withinMemoryTolerance()`（`include/control_logic.h`），`selftest` 改用容差判定并打印 PSRAM 堆拆分；`status` 的 `PSRAM=` 标签改为 `PSRAM_heap=` 以免再次误读。该策略已加入主机测试。

### Wi-Fi 连接：凭据处理与实测边界

`wifi connect <SSID> <密码>` 是可选的一次性联通测试，不是最终产品的配网方案。设计约束如下：

- **只存 RAM，绝不写 flash。** Arduino-ESP32 的 `WiFiGenericClass::_persistent` 默认是 `true`，直接 `WiFi.begin()` 会把口令提交到 NVS。固件在连接前显式调用 `WiFi.persistent(false)`。
- **实测验证**：连接成功后用 esptool 读出 NVS 分区（0x9000、20 KiB）逐字节检查，`stkj` 口令、SSID 的 UTF-8 字节、以及 `sta.ssid`/`sta.pswd`/`sta.config` 三个键**均不存在**；分区 89% 为 `0xFF`，`nvs.net80211` 中只有 SDK 默认的 `WIFI_STA_DEF`、`cal_data`、`phy`、`dhcp_state` 等条目。
- **复位即失效**：硬复位后 `wifi status` 返回未连接（status=255），RAM 中的凭据随之下线。
- **不回显**：口令从不回显、不进入 `status`，`stop`/`!` 会连同 Wi-Fi 一起关闭射频。
- 口令上限受 96 字节命令行长度限制；SSID 支持 UTF-8（为此把行缓冲的非 ASCII 过滤去掉，只保留控制字符过滤），并有主机测试覆盖。

以上仅为一次联通性验证，**不代表语音/联网应用固件已完成**。

主控的芯片、存储器、Wi-Fi、LED 与按键已于 2026-09-10 实测通过。以下仍未测：

- **屏幕**：实物 12 针朝向与焊点、外部 3.3V 供电、全亮/刷新电流、色条与方向/反色、EC11 每格计数、PUSH/KEY0 计数。
- **舵机**：5V 电源能力与限流、实物 S/正/负 针序、1500μs 首次中位、1000–2000μs 空载动作（两路）、启动电流与压降。
- **整机**：8 舵机同时负载、屏幕/语音/Wi-Fi 并发、温升、PCB 打样与机械配合、步态与声学。

自检向导只验证“流程能不能走完、门禁会不会拦住”，它本身不测任何电气量。`--rehearse` 的输出是步骤清单，**不是实测结果**。

USB与外部供电的受控时序必须按接线说明执行；软件不提供未供电器件的硬件隔离。单舵机超时仅停发PWM，不切断5V。以上结果不是PCB打样、整机负载或机械配合的批准。
