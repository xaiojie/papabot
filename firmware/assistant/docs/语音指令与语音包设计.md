# 桌面助手 · 语音指令 + 固定语音包（设计 v1）

> 状态：**设计阶段，未实现**
> 定位：**不用大模型**的语音交互 —— 说一句指令，设备播一段预录好的语音
> 关系：AI 对话版设计见 `语音AI功能设计.md`（**留作备选**）

---

## 1. 功能定义

```
你按一下（或喊一声）  →  设备开始听
你说「看看天气」      →  识别出指令
                      →  屏幕切到天气页
                      →  喇叭播「好嘞，这就给你看」
```

**明确不做的**：
- ❌ 不接大模型，不做自由对话
- ❌ 不做语音合成（TTS）—— 播的是**预先做好的音频文件**
- ❌ 不生成新句子

**为什么这样反而更好**：

| 好处 | 说明 |
|---|---|
| **声音好听** | 语音包可以是任何声音 —— 你自己录、专业配音、或最好的 TTS 离线生成。不受嵌入式 TTS 机械音的限制 |
| **延迟极低** | 识别完直接读 flash 播放，没有合成等待 |
| **完全确定** | 每次说的话一模一样，不会"发挥" |
| **成本为零** | 不消耗任何 API token |
| **可离线**（走本地识别时）| 断网也能用 |

## 2. 两条技术路线

### 路线 A：云端 ASR + 服务端匹配 → 播本地语音包 ⭐ **建议先做**

```
设备录音 ──POST /asr──> 服务端 ASR ──> 关键词匹配 ──> 返回指令 ID
                                                      │
设备读 flash 里对应语音包 <───────────────────────────┘
```

| 优点 | 缺点 |
|---|---|
| 复用阶段 0 的服务端（**只需要 ASR，不用 DeepSeek/TTS**）| 要联网 |
| **改命令词只需改服务端一个文本文件，不用重烧固件** | 延迟 ~1–1.5 s |
| 不占 flash（不需要 esp-sr 模型）| |
| 自由说法容错好（"天气怎么样" / "今天天气" / "看看天气" 都能匹配）| |

### 路线 B：本地 MultiNet 命令词识别 → 播本地语音包

用 ESP-SR 的 **WakeNet（唤醒）+ MultiNet（命令词）**，全部在设备上跑。

| 优点 | 缺点 |
|---|---|
| **延迟 < 500 ms** | 要烧 esp-sr 模型，占 flash |
| **完全离线**，断网可用 | 需要改分区表 |
| 隐私最好（音频不出设备）| 命令词要在模型里，靠 `esp_mn_commands_add()` 动态改 |
| 误触发低（官方数据：12 小时一次）| 必须配 WakeNet，唤醒词要先定 |

### 建议

**先做 A，B 留作升级。**

理由：A 的改动小（服务端加个 ASR + 匹配，设备加个"录音上传 + 播语音包"），而且**迭代快** —— 想加一条指令，改服务端一个词条就行。

等命令表稳定了、想离线了，再上 B。

## 3. 语音包存哪 —— flash 预算实测

当前 app 分区 **3,342,336 字节**，已用 42%，**剩 1,875 KB**。板子上**没有 TF/SD 卡座**，所以只能靠内部 flash。

| 格式 | 码率 | 1,875 KB 能存 |
|---|---|---|
| 16 k / 16 bit PCM | 31.2 KB/s | 60 秒 |
| 24 k / 16 bit PCM | 46.9 KB/s | 40 秒 |
| **16 k / IMA-ADPCM (4 bit)** | **7.8 KB/s** | **240 秒（4 分钟）** |

### 推荐：IMA-ADPCM

- **2:1 压缩**（相对 16 bit PCM），但相对 mp3/opus 解码器**几乎不占 flash**
- 解码器约 **20–30 行代码**，零依赖
- 240 秒够放 **120–200 条** 1–2 秒的短句

> 如果以后要更多，再考虑 Opus（解码器约 100 KB flash，能再压 4 倍）或加外挂 SPI Flash。

### 存储布局

在 app 分区之后加一个 `voice` 数据分区，或者直接把语音包**嵌进固件**（`board_build.embed_files`，和现在中文字体的做法一样）。

**建议先嵌入固件**（最简单，和现有中文字模同一套机制）：

```
firmware/assistant/data/
  voice.idx      # 索引：ID → 偏移/长度
  voice.pcm      # ADPCM 数据
```

## 4. 命令表设计

### 起步命令表（配合现有六屏）

| ID | 你说（任一句都行）| 动作 | 语音包 |
|---|---|---|---|
| 1 | 你好 / 嗨 / 在吗 | — | 「你好呀，我是爬爬」|
| 2 | 看看天气 / 天气怎么样 / 今天天气 | 切**天气屏** | 「长沙今天阴，你看屏幕」|
| 3 | 现在几点 / 几点了 | 切**时钟屏** | 「现在三点二十」|
| 4 | 看表情 / 变个脸 | 切**表情屏** | 「嗯哼～」|
| 5 | 我回来了 | 表情→**开心** | 「欢迎回来！」|
| 6 | 晚安 / 睡觉了 | 表情→**困** | 「晚安，做个好梦」|
| 7 | 额度 / 还剩多少 | 切**额度屏** | 「额度看屏幕吧」|
| 8 | 状态 / 你怎么样 | 切**状态屏** | 「一切正常」|
| 9 | 别说了 / 安静 | 停止播放 | （静音）|
| 0 | 其它（没匹配上）| — | 「我没听清，再说一次？」|

### 动态数值怎么办 —— 两种做法

**做法一：让用户看屏幕**（最简单）
语音只说固定部分，具体数字显示在屏幕上。上面表里就是这么写的。

**做法二：语音包拼接**（进阶，效果更好）
把数字和单位单独录成短音频，播放时拼起来：

```
「现在」+「下午」+「三」+「点」+「二十」+「分」
```

只需要录 **0–9、十、百、点、分、度、度到、月、日、星期** 等约 30 条短音频，就能拼出**无限多的数字**。

> 建议：**v1 用做法一**（先跑通），v2 加拼接。

## 5. 交互设计

### 怎么开始说话

| 方式 | 优点 | 缺点 |
|---|---|---|
| **按键说话**（屏上 KEY0 / 旋钮按下）| 零成本、100% 可靠、无误触发 | 要伸手 |
| **唤醒词**（路线 B）| 免动手 | 要烧模型、可能误触发 |

**建议先做按键**：按一下 → 播一声短促「叮」→ 开始听 → 静音 1 秒自动结束。

### 状态机

```
IDLE ──按键──> PROMPT(播"叮") ──> LISTENING ──静音1秒──> RECOGNIZING
  ^                                   │                       │
  │                              再按一次取消                  │
  │                                                           v
  └────────── PLAYING(播语音包) <── 匹配到指令 ID ──────── MATCHED
                    │                                   │
                    └──────── 没匹配上 → 播"没听清" ─────┘
```

### 屏幕联动（复用现有表情屏）

| 状态 | 表情 |
|---|---|
| PROMPT / LISTENING | 眼睛睁大，底部**麦克风电平条**（实时音量，让你知道它在听）|
| RECOGNIZING | 眼睛转向一侧 + `···` |
| PLAYING | **嘴跟着音频包络张合** |
| 没听清 | 难过表情 + 屏幕显示**识别到的原文**（关键！能立刻看出是听错了还是没这条命令）|

> 「显示识别原文」很重要。不然你不知道是设备没听见，还是听错成了别的词。

## 6. 语音包怎么制作

需要的工具链：**文本 → 音频 → 格式转换 → ADPCM → 索引头文件**

建议写一个脚本 `scripts/make_voice_pack.py`：

```
读 voice_lines.csv（ID, 文本）
  → 调 edge-tts 生成 mp3（免费、中文自然，可换各种音色）
  → ffmpeg 转成 16k/16bit/mono
  → 编码成 IMA-ADPCM
  → 拼成 voice.pcm + voice.idx
```

同时生成一张**试听页**（HTML），你在浏览器里就能听每一条对不对。

### 声音从哪来

| 来源 | 说明 |
|---|---|
| **Edge-TTS** | 免费，中文音色多（晓晓/云希/晓伊…），质量很好 ⭐ 推荐起步 |
| **自己录** | 最有特色（比如家人的声音），但要安静的录音环境 |
| **云厂商 TTS** | 阿里/腾讯/讯飞，音色更多，要开通 |
| **自建** | GPT-SoVITS / CosyVoice，可以克隆音色，需要 GPU |

> 因为语音包是**离线生成的**，所以可以用最好的方案，完全不占设备算力。

## 8. 硬件依据（已确认）

| 件 | 型号 | 关键参数 |
|---|---|---|
| 麦克风 | **MSM261S4030H0**（Sipeed I2S_Mic / SEN0327）| I2S 数字输出，**24 bit 装在 32 bit 槽**（固件右移 8 位）；灵敏度 −26 dBFS；SNR 57 dB；BCLK 150–800 kHz |
| 功放 | **MAX98357A** | I2S，**RevB 是左对齐**；BTL 输出 `SPK_P`/`SPK_N` 两端不接地 |

**引脚**（PCB 已预留，且麦克风与功放**分属两个独立 I2S 域**）：

```
MIC_BCLK = L4    MIC_WS = L5    MIC_SD = L6
AMP_BCLK = R5    AMP_WS = R6    AMP_DIN = R7
```

**两条硬件红线**（不可违反）：
1. MAX98357A 的 `SD_MODE` **禁止接 GPIO 或 5V 上拉**（会回灌 GPIO）
2. 功放 5V 走**独立短粗线**，不经 J6 小信号插头

**采集参数**：16 kHz / 16 bit / 单声道，`MIC_LR_GND` 选左声道，BCLK = 16 k × 32 = **512 kHz**（在规格内）

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **回声**：喇叭声被麦克风听到 | 可能自己触发自己 | **半双工**：播放时完全不录音。先这么做 |
| **识别错** | 播错语音包 / 切错屏 | 屏幕上**显示识别原文**，一眼看出问题 |
| **网络不稳**（路线 A）| 说了没反应 | 明确提示"网络不通"；v2 可上路线 B 离线 |
| **环境噪音**（57 dB SNR 的麦克风）| 识别率下降 | 服务端 ASR 抗噪通常够；必要时加 AFE 降噪 |
| **功放电流尖峰** | 可能拉低电源 | 电池标称 ≥10A；功放 5V 独立走线（PCB 已如此设计）|
| **flash 不够装更多语音** | 只能存 240 秒 | 先嵌入固件；不够时加 Opus 压缩或外挂 SPI Flash |

## 10. 分期计划

### 阶段 0 —— 不用等硬件 ⭐ 可以先做

- 写 `make_voice_pack.py`：文本表 → Edge-TTS → ADPCM → 索引
- 生成**试听页**，你确认每条语音对不对、声音喜不喜欢
- 定稿命令表和说法
- 服务端加 `/asr` 接口（只做 ASR + 匹配）

### 阶段 1 —— 音频硬件打通（需要麦克风 + 扬声器）

- 开发板飞线接 I2S 麦克风和 MAX98357A
- 录一段回放，确认采样率/声道/位深
- 按键说话 + 提示音 + 播语音包

### 阶段 2 —— 端到端

- 接上服务端 ASR
- 命令匹配 → 切屏 + 播语音包
- 嘴型同步
- 屏幕显示识别原文

### 阶段 3 —— 打磨

- 数字拼接（能念具体时间/温度）
- 路线 B：本地离线识别
- 唤醒词

## 12. 与备选方案（AI 对话）的关系

两者**共用大部分底座**：

```
共同：音频编解码 / I2S 收放 / 语音包存储与播放 / 状态机 / 表情联动
        │
        ├─ 本方案：命令词匹配 → 播固定语音包     ← 简单、快、可控
        └─ 备选：ASR → DeepSeek → TTS → 播语音   ← 灵活、能对话、要 TTS
```

**先做本方案是划算的**：音频硬件、编解码、播放、状态机这些**做完之后两个方案都能用**。将来想加 AI 对话，只需把"匹配命令"换成"发给 DeepSeek"，其余不动。

> 换句话说：**本方案是 AI 方案的地基，不是弯路。**
